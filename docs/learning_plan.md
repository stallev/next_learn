# План изучения Zustand в Next.js

Этот план поможет вам поэтапно освоить библиотеку Zustand, переходя от простых концепций к сложным, используя созданное приложение в качестве песочницы.

## Этап 1: Основы (Store и State)
**Цель:** Понять, как создавать хранилище и использовать его в компонентах.
1.  **Установка:** Добавьте zustand в проект (`npm install zustand`).
2.  **Создание Store:** Создайте простой store для счетчика или переключения темы.
3.  **Использование в компоненте:** Замените локальный `useState` в простом компоненте на состояние из Zustand.
4.  **DevTools:** Подключите Redux DevTools middleware для отладки.

## Этап 2: Асинхронные действия (Async Actions)
**Цель:** Научиться работать с API через Zustand.
1.  **Миграция постов:** Перенесите логику загрузки постов из `PostList.tsx` в Zustand store.
2.  **Обработка состояний:** Реализуйте состояния `loading`, `success`, `error` внутри store.
3.  **Вызов action:** Вызовите действие загрузки (`fetchPosts`) в `useEffect` компонента.

## Этап 3: Селекторы и Оптимизация (Selectors)
**Цель:** Избежать лишних ререндеров.
1.  **Использование селекторов:** Попробуйте доставать из store не весь объект, а только нужные поля (например, `useStore(state => state.posts)`).
2.  **Сравнение:** Изучите, как Zustand сравнивает объекты (shallow comparison).

## Этап 4: Сохранение состояния (Persist Middleware)
**Цель:** Научиться сохранять состояние приложения между перезагрузками страницы.
1.  **Подключение middleware:** Оберните store в `persist` middleware.
2.  **Конфигурация:** Настройте имя хранилища (`name`) и выберите `storage` (по умолчанию `localStorage`).
3.  **Избранное:** Реализуйте функционал "Избранные посты" и сохраняйте их, чтобы они не пропадали после F5.
4.  **Гидратация:** Разберитесь, как работает восстановление состояния (rehydration) и как избежать ошибок гидратации в Next.js (Text content does not match server-rendered HTML).

## Этап 5: Разделение Store (Slices Pattern)
**Цель:** Организация кода в больших приложениях.
1.  **Создание слайсов:** Разделите большой store на несколько независимых частей (slices), например `createPostSlice` и `createUserSlice`.
2.  **Объединение:** Соберите слайсы в один store.

## Этап 6: Zustand + Next.js (SSR/RSC)
**Цель:** Правильное использование в Server Components и Client Components.
1.  **Проблема гидратации:** Изучите, почему нельзя просто так использовать глобальный store в SSR.
2.  **Context Provider:** Создайте Store Provider для изоляции состояния на уровне запроса (актуально для App Router).

## Практическое задание
После изучения каждого этапа, создавайте ветку или отдельный файл в проекте, демонстрирующий пройденный материал.
